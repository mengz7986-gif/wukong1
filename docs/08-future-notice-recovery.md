# 取消与人工账款通知恢复

独立的 `newbot-cancel-notices` 服务处理未来取消回执，以及新增待付、收款、预存抵扣和推送账单中从未发送的通知。它不导入业务模型，也不启用接单、学习、分单或账单批处理任务。后台的 `RAINBOW_DISABLE_BACKGROUND_WORKERS=1` 保持不变。

`/etc/newbot/cancel-notices-policy.json` 中的 `activated_at` 是本次用户批准的启用时间边界；`future_account_notices_enabled=true` 开启人工账款通知处理。部署时必须先保存旧策略，再使用带时区的当前时间设置边界，不能沿用历史日期，否则会补发旧消息。

仅认领边界后创建、状态为 `pending` 且 `attempts=0` 的通知。取消回执继续校验取消事实和消息来源；账款通知采用事务中已经保存的通知内容与目标。认领使用与后台接口相同的原子状态变更，避免后台和独立服务重复发送。历史记录不改写、不删除，边界前积压保持隔离；`sending`、`unknown`、`failed` 和 `canonical_alias` 不自动重发。网络超时按送达不明处理。

服务使用 SQLite 授权器，只允许修改通知的发送状态、尝试次数、错误类别和发送时间；不允许改写订单、库存或账务。重启自动恢复限于进程异常退出，人工停止不会自动重启。

本地验证：`python3 -m unittest discover -s tests -p 'test_future_account_notices.py' -v`。所有发送均使用模拟回调和临时数据库，禁止用生产订单测试。
