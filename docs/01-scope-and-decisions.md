# 范围、状态机与首版决策冻结

日期：2026-10-21。范围仅为彩虹仓酒店液体香薰后台与 Telegram 接单机器人。

## 本阶段交付边界

本阶段建立本地离线骨架、空业务数据库、示例目录、核心识别预览确认流程及可追溯需求映射。它不是生产服务器、不是生产机器人、不是完整系统，也不含数据迁移或生产切换。

## 继承

- 74 项原需求＋11 项跟踪的业务意图和验收边界；逐项见 `02-requirements-traceability.md`。
- Canonical 标准目录、正式已审核别名、规则版本与人工审核门槛的模型。
- 本地 Parser 优先、AI 有界补救、最终 Validator 不可绕过。
- Bot 与后台的认证、幂等、重复消息防护、超时后查询提交结果和持久回执原则。
- 价格继承、仓库选择、运费、单位、分单均为显式配置，不硬编码旧示例值。
- 北京时间自然日、FIFO、财务原子守恒、分单前序成功与同地址额度。
- 所有管理写入保存实际认证操作者、前后变化、结果、幂等操作 ID 和关联实体。

## 明确不复制

- 任何生产 Token、Key、Cookie、密码、Webhook、真实 Telegram 身份或管理员名单。
- 客户资料、历史订单、价格实值、余额、收款、库存、成本、Outbox、通知或租约。
- 旧 SQLite 数据库、WAL/SHM、日志、备份、消息原文或可还原客户的学习证据。
- 旧文件数、表数、部署回执编号、73/74 表硬限制及旧项目专用发布工具。
- 已退役风火递集成；旧知识库固定“6 支”规则；历史缺证猜测和旧缺陷。
- 历史通知重发、历史分单补推、旧余额倒算或缺失证据补造。

## 待正式确认或补充

- 脱敏且经批准的 Canonical 商品目录、有效别名版本及适用仓库。
- 实际价格继承、运费档位、仓库启停、品类/地址限额与分单配置值。
- 哪些客户未来允许自动录单；首版一律预览后确认。
- Telegram、DeepSeek、阿里云地址、汇率与未来物流的测试/生产凭证和接口契约。
- 逐接口完整 schema、错误码与角色权限矩阵；生产迁移、未决任务处置、切换及回滚方案。

## 分离状态机

订单、录单、付款、物流、通知分别存储，禁止以单一状态代替多个事实：

| 领域 | 首版状态方向 |
|---|---|
| 订单 | draft → previewed → confirmed / rejected / cancelled |
| 录单 | pending → recording → recorded / failed / unknown |
| 付款 | unpaid → partial → paid / refunded |
| 物流 | unshipped → shipped → delivered / exception |
| 通知 | pending → sending → sent / failed / unknown |

`unknown` 不是成功，也不自动进入重发。任务超时必须先按幂等键或来源消息查询服务端事实。

## 权限冻结

角色至少包含 owner、admin、customer、service、anonymous。UI 可见性不代表 API 授权；每个写接口都必须在后端用有效载荷验证。客户端传入的 `operator` 只能是兼容字段，审计操作者必须来自认证上下文。

## 验收冻结

核心链先统一验收：接收 → 本地标准化 → 预览 → 确认 → 事务提交 → Outbox。后续阶段再增加真实价格/库存/分单/财务/学习/UI。全系统完成声明必须同时包含 API 权限有效载荷测试、390/1440 浏览器测试及端到端结果，模块单测不能替代。
